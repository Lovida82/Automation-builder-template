# PRD 추가 합의 사항 (이 사례 전용)

> 기본 `AUTOMATION_BUILDER_PRD.md` 외에, 이 사례를 진행하며 Claude와
> 추가로 합의해 `DECISIONS.md`에 기록했던 내용을 일반화한 것입니다.
> 비슷한 업무를 만드는 분이 참고할 수 있게 더미 값으로 정리했습니다.

---

## 프로젝트 정의 (0-1 답변)

```
1) 자동화 업무
   매일 아침 SAP 웹포털에서 전일 판매실적을 다운로드해 Excel로 정리

2) 자동화 대상
   웹사이트 (사내 SAP 웹포털) + 파일 시스템 작업 (다운로드 파일 이동)

3) 경로 선택
   웹포털 (PRD 기본 권장값 그대로)

4) 실행 시점
   매일 오전 8:30, 수동 실행 (출근 후 버튼 클릭)

5) 최종 결과물
   output/판매실적_YYYYMMDD.xlsx 저장
```

## 핵심 의사결정 (DECISIONS.md 발췌, 더미화)

```markdown
## 프로젝트 시작
- 자동화 대상: SAP 웹포털 + Excel 후처리
- 선택한 경로: 웹포털 (사용자 선택, PRD 디폴트)
- 실행 빈도: 매일 오전 8:30 수동 실행
- 최종 결과물: output/ 에 판매실적_YYYYMMDD.xlsx 저장
- 자격증명 저장: Windows 자격증명 관리자(keyring)
- 포털 URL: https://sap.example.com  (더미)

## Step 1 (로그인) 설계
- 로그인 방식: ID/PW 직접 입력 (SSO 미사용)
- 로그인 실패 시: 3회 재시도 후 GUI에 에러 표시

## Step 3 (조회) 설계
- 조회 날짜: 시작일=종료일=어제 (코드에서 자동 계산, 기본값)
- 거래처 코드: 비움 (전체 조회)
- 결과 로딩: 결과 테이블 첫 행 출현까지 최대 30초 대기
- 결과 0건일 때: 빈 파일 생성하지 않고 "조회 결과 없음" 알림

## Step 5 (후처리) 설계
- 파일명 규칙: 판매실적_{조회일 YYYYMMDD}.xlsx
- 같은 이름 존재 시: _2, _3 ... 접미사 부여 (덮어쓰기 안 함)
```

## 변수화한 값

| 값 | 출처 | 비고 |
|----|------|------|
| 사용자 ID / PW | GUI 입력 → keyring | 첫 실행 시 1회 입력 |
| 조회 날짜 | 코드 자동 계산 (어제) | GUI에서 수동 변경도 가능 |
| 결과 저장 경로 | 기본 output/ | GUI에서 변경 가능 |

## 식별한 화면 요소 (예시, 더미 셀렉터)

> 실제 셀렉터는 각자의 포털에 따라 다릅니다. 형태 참고용.

```
- ID input        : input[name="userId"]
- PW input        : input[name="password"]
- 로그인 버튼      : button:has-text("로그인")
- 판매현황 메뉴    : a:has-text("판매현황")
- 시작일 input    : input[name="dateFrom"]
- 종료일 input    : input[name="dateTo"]
- 조회 버튼        : button:has-text("조회")
- 결과 테이블      : table#resultGrid   (이 요소 출현 = 로딩 완료)
- 엑셀 다운로드     : button:has-text("엑셀 다운로드")
```
